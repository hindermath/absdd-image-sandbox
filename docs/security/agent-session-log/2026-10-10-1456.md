# Native Architektur und Sandbox-Neubau / Native Architecture and Sandbox Rebuild

## Deutsch

- Auftrag: den genehmigten Architektur-Guard umsetzen, Image und Container
  erneuern, Nutzerdaten erhalten und nur veraltete Sandbox-Ressourcen entfernen.
- Compliance-Bezug: P1-4 technisch teilweise bearbeitet durch erneute lokale
  Validierung. Keine formelle Sandbox-Freigabe, Providerfreigabe, Secret-Rotation
  oder Plattformadministration vorgenommen; diese bleiben menschliche Aufgaben.
- Bash- und PowerShell-7-Pruefung fuer Hardware, Podman, Zielplattform und
  Image ergaenzt. Native Ausfuehrung ist Standard; Cross-Build braucht eine
  explizite Plattform und einen zusaetzlichen Freigabeschalter. Unbekannte
  Werte und widersprechende Plattformvorgaben brechen ab.
- Beide SBOM-Einstiege verwenden den Guard, auch bei SkipBuild und Dry-run.
  Der neue Compose-Lifecycle-Einstieg prueft vor Build, nach Build und vor
  Start. `up` behaelt vorhandene Container und verweigert veraltete Images;
  `recreate` ist ein ausdruecklicher Austausch nach Sicherung. Direkte
  Compose-Befehle umgehen den Host-Guard; README und Betriebsdokumentation
  erklaeren diese Grenze deutsch zuerst und englisch danach.

## English

Implemented native-by-default Bash and PowerShell architecture guards and
guarded Compose lifecycle entrypoints. Built and checked image `381e06ecb72f`
as `linux/arm64`, verified 16 native ELF executables, generated the CycloneDX
SBOM, and replaced the container only after successful image tests. All
original mounts and named volumes were retained; all 7184 previously recorded
agent-volume files were unchanged after replacement. Eleven selected user-data
files and one verified internal symlink were restored from access-restricted
local backups. Old binaries, caches, and locks were not restored. Restart and
both lifecycle entrypoints passed; the obsolete sandbox container and image
were removed without global pruning or volume deletion.

All 13 regression tests passed on macOS and inside the Linux container.
Toolchain compilation, documentation generation, live agent CLI checks,
static analysis, and repository hooks passed. A supplementary directory scan
reported only two false positives for the public Swift signing fingerprint;
no scanner rules were weakened. The existing Swift GPG expiry/permissions
warnings were recorded without bypassing signature verification. Dedicated
Windows/WSL2, Intel, and standalone Linux hosts were unavailable. Technical
revalidation contributes partially to P1-4, not formal human approval. No
credentials were printed, no sign-in or writable Home Runtime sync was run,
and no Git delivery or autonomous Spec Kit run was started.
