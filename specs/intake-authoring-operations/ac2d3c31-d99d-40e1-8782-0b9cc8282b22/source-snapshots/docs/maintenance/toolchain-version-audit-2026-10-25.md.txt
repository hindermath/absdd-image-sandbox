# Versionsabgleich / Version Audit 2026-10-25

## Auftrag und Grenze / Authority and Boundary

DE: Der Owner beauftragte aktuelle stabile Werkzeugversionen und bestaetigte
Hauptversionswechsel; Java, Node und .NET sollen bevorzugt LTS verwenden.
LTS bedeutet langfristig unterstuetzte Versionslinie. Dieser Abgleich aendert
keine Provider, Modelle, Zugangsdaten, Freigaben oder Plattformregeln und startet
keinen Spec-Kit-Produktlauf. Keine Commits oder Pushes sind beauftragt.

EN: The owner requested current stable tools and confirmed major upgrades,
preferring long-term support (LTS) lines for Java, Node and .NET. This audit
does not change providers, models, credentials, approvals or platform rules or
start a Spec Kit product run. No commit or push is authorized.

## Integritaet und Paketquellen / Integrity and Package Sources

DE: Das MCR-Manifest
`sha256:747cbade5bfd918a175ac32f8f1d931edec2c7d0d5397a3de72eaef1ac1f66d2`
enthaelt native Linux-AMD64- und ARM64-Images. Beide Config-Blobs melden SDK
10.0.402 und Ubuntu 24.04; ihre Historie enthaelt PowerShell 7.6.7. Deshalb
wird das vorhandene globale Tool aus Microsofts offiziellen 7.6.8-Paketen
aktualisiert und anschliessend per Versionsaufruf geprueft. Die im Dockerfile
festen SHA-256-Werte stammen aus den aktuellen offiziellen
dotnet-docker-Installationsdefinitionen fuer beide Architekturen.

EN: The MCR index contains native Linux AMD64 and ARM64 images. Both config
blobs declare SDK 10.0.402 and Ubuntu 24.04, with PowerShell 7.6.7 in their
history. The existing global tool is therefore updated using official
Microsoft 7.6.8 packages and checked afterwards. Committed SHA-256 hashes come
from the current official dotnet-docker definitions for both architectures.

DE: Aktualisierte Pandoc-, Tinymist- und Antigravity-Hashes kommen aus den
offiziellen Release-Asset-Digests. Go-Hashes kommen aus go.dev, SDK-SHA-512
aus Microsofts Release-Metadaten. Unveraenderte Lychee-, Typst- und
actionlint-Hashes stimmen mit ihren aktuellen Release-Assets ueberein.
Swift behalt seine PGP-Signaturpruefung; uv, rustup und Syft behalten ihre

EN: Updated Pandoc, Tinymist and Antigravity hashes come from official release

assets. Swift keeps PGP verification; uv, rustup and Syft keep checksum checks.
npm installs exact versions with registry integrity metadata. No AMD64 fallback
is introduced for ARM64.

## Kompatibilitaet / Compatibility

DE: OpenCode 2 erhaelt eine native geordnete `permissions`-Liste. Jede bisherige
Regel bleibt mit gleicher Reihenfolge, Ressource und Wirkung enthalten;
`bash` wird `shell`, `task` wird `subagent`. Globale Standardregel bleibt `ask`,
Secret-Dateien und destruktive Kommandos bleiben blockiert. Sitzungsfreigabe
und automatische Updates bleiben aus. Der Regressionstest prueft alle Regeln
gegen die eingefrorene V1-Fixture und ausgewaehlte Schutzfaelle. Er ist kein
Nachweis gegen beliebige Shell-Umgehungen oder geaenderte Agentenregeln.

EN: OpenCode 2 uses native ordered permissions. Every previous rule retains
order, resource and effect; bash becomes shell and task becomes subagent.
The global default remains ask, secret files and destructive commands remain
blocked, and sharing/automatic updates stay disabled. Regression tests compare
all rules with the frozen V1 fixture and selected security cases. This does not
prove protection against arbitrary shell bypasses or changed agent overrides.

DE: `doom_loop` und `lsp` sind laut V2-Dokumentation keine aktuellen Core-
Berechtigungsaktionen. Die Regeln bleiben fuer Erweiterungen erhalten, stellen
aber keinen belegten V2-Loop-Schutz dar. Vor Provider-Nutzung benoetigt dieser
Punkt einen gezielten Review; keine pauschale Sicherheitsparitaet behaupten.
V2 teilt Konfigurationsorte mit V1: Daten vor erster Nutzung sichern und keine
Rueckwaertskompatibilitaet des neuen Formats mit V1 behaupten.

EN: doom_loop and lsp are not current V2 Core permission actions. Their rules
remain for extensions but do not prove V2 loop protection. Review this before
provider use; do not claim complete security parity. Back up data before V2
use and do not claim V1 compatibility for the new configuration format.

DE: Spec Kit 1.2.3 ist auf den aufgeloesten Release-Commit
`5ea8b1cf0a38699340a38e00d02770308997d8c0` gepinnt. Der enge Bind-Mount-Patch
greift vor dem Import der Kopiermodule; der neue Einstieg ohne `import json`
ist abgedeckt. Unbekannte Modulstrukturen werden weiterhin abgelehnt.
Keine bestehenden Projekt-Presets oder Feature-Artefakte werden neu generiert.

EN: Spec Kit 1.2.3 is pinned to its peeled release commit. The narrow bind-mount
patch runs before copying modules are imported, including the new entrypoint
without import json. Unknown layouts remain rejected. Existing project presets
and feature artifacts are not regenerated.

## Bisherige Pruefungen / Checks So Far

DE: 57 fokussierte Regressionstests sind bestanden: OpenCode-/Syft-Vertrag 5,
Spec-Kit-Patch 4, JSON-Preflight 5, Agent-Surface-Paritaet 6, Prompt-Dispatcher 4
und Hardening-Validator 28 sowie Versions-/Install-Hook-/Runtime-Pins 5. Compose-Konfiguration, PowerShell-/Bash-Syntax,
Renovate-Schema und OpenCode-Schema sind erfolgreich geprueft. Die neuen
OpenCode-Regeln wurden ausserdem vom echten 2.1.4-CLI aus einem isolierten Home
gelesen; `run --help` bleibt mit dem Dispatcher kompatibel. Spec Kit 1.2.3
erzeugte ein isoliertes OpenCode-Testprojekt mit zehn Commands, ohne Git-Repo.

EN: All 57 focused regression tests passed: OpenCode/Syft contract 5, Spec Kit
patch 4, JSON preflight 5, agent surface parity 6, prompt dispatchers 4 and
hardening validator 28 plus version/install-hook/runtime pins 5. Compose configuration, shell syntax and Renovate and
OpenCode schemas passed. The real OpenCode 2.1.4 CLI read the rules from an
isolated home and its run help remains compatible with the dispatcher. Spec Kit
1.2.3 generated ten commands in an isolated OpenCode project without Git.

DE: Gitleaks fand im vollstaendigen Snapshot einmal den unveraenderten
oeffentlichen Swift-PGP-Fingerprint in `Dockerfile`. Das ist kein Secret.
Der separate Scan des tatsaechlichen Aenderungsumfangs plus neuer Dateien
fand keine Secrets. Keine Allowlist wurde erweitert. Initiale Pruefversuche
mit dem entfernten Spec-Kit-Flag `--no-git` beziehungsweise ohne erlaubte
Schema-Referenzaufloesung wurden korrekt abgewiesen und mit passender Syntax
erfolgreich wiederholt; sie gelten nicht selbst als bestandene Tests.

EN: Gitleaks flagged the unchanged public Swift PGP fingerprint once in the
full snapshot; it is not a secret. A separate scan of actual changes plus new
files found no secrets. No allowlist was broadened. Initial attempts using the
removed Spec Kit no-git flag or disabled schema reference resolution were
correctly rejected, then successfully repeated with supported syntax. Those
initial attempts are not counted as passing checks.

## Verbleibende Grenzen / Remaining Boundaries

DE: Im ersten Runtime-Smoke brachte das Kompatibilitaets-SDK zusaetzlich
Runtime 10.0.11 mit. Das finale Image behaelt beide SDKs, stellt den originalen
Host aus dem unveraenderten MCR-Basisstage wieder her und entfernt aeltere
Runtime-/hostfxr-Patches derselben 10.0-Linie. Nur Runtime 10.0.13 bleibt aktiv
installiert. Das betrifft ausschliesslich Image-Pfade, keine Datenvolumes.

EN: The first runtime smoke exposed an additional 10.0.11 runtime from the
compatibility SDK. The final image keeps both SDKs, restores the original
host from its immutable MCR base stage and removes older runtime/hostfxr patches
of the same 10.0 line. Only runtime 10.0.13 remains installed. Data volumes are
not involved.
